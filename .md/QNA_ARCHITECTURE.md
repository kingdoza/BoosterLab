# QnA — 설비 배치·회수 및 락커·열쇠 정책

각 질문의 `답변:` 줄에 선택지 문자 또는 직접 답변을 입력한다.

## Q59. 서로 다른 기존 설비 액터에 배치 기능을 붙이는 공통 구조는?
- A: `IPlaceableFacility` 계약과 `UFacilityPlacementComponent`를 기존 설비 액터에 조합한다.
- B: 모든 설비를 새 공통 배치 액터 클래스로 재상속한다.

- 권장안: A — 현재 일반 설비와 세탁기·건조기의 상속 계층을 유지하면서 공통 계약만 통일할 수 있다.
- 답변: A

## Q76. 기존 손님 루틴의 신발 관련 단계는?
- A: `신발 넣기`와 `신발 착용` 활동·상태·전이를 모두 제거한다. StateTree Editor 작업량: 중간, 두 상태와 관련 전이·바인딩 삭제.
- B: 표현 없이 시간만 소비하는 단계로 유지한다. StateTree Editor 작업량: 낮음.
- C: 탈의와 착의 시간에 각각 합친다. StateTree Editor 작업량: 낮음, duration 구성만 수정.
- 권장안: A — 구현하지 않는 신발 도메인과 폐기된 신발장 의존성을 루틴에서 완전히 제거한다.
- 답변: A. 신발은 구현하지 않는다.

- A: 일대일 대응하지 않고, 열쇠는 체크인·체크아웃용 반환 토큰으로만 사용한다.

- C: 열쇠 번호와 락커 번호를 영구적으로 일대일 대응시킨다.
- 권장안: A — 묶음 락커 배치·회수와 무관하게 같은 물리 열쇠를 반환할 수 있고 번호 재할당도 제거된다.
- 답변: A

## Q80. 확장 단계의 열쇠 수와 최대 설치 락커 칸 수 관계는?
- A: 모든 단계에서 `KeyPoolSize >= MaxInstalledLockerSlots`를 검증해 정상 운영에서는 열쇠가 구조적 수용량을 제한하지 않게 한다.

- 권장안: A — 실제 수용량은 락커에 종속된다는 정책을 보장하면서 물리 열쇠 부족은 반환 지연 같은 운영 상태로만 남긴다.
- 답변: A

- C: 배치 판정영역의 바닥 면적 합계로 계산한다.

- 답변: A

## Q82. 손님의 수용량 Lease는 언제 획득·반환하는가?
- A: 체크인 열쇠 전달 성공 시 획득하고 체크아웃·timeout·technical cleanup에서 정확히 한 번 반환한다.
- B: 탈의를 시작할 때 획득하고 목욕탕에서 나온 직후 반환한다.
- C: 손님 spawn 시 획득하고 Actor EndPlay에서만 반환한다.
- 권장안: A — 플레이어가 입장을 승인한 손님만 수용량을 점유하고 모든 정상·비정상 종료 경로를 대칭 처리할 수 있다.
- 답변: A

## Q83. 손님은 탈의와 착의에 어떤 락커 지점을 사용하는가?
- A: 입장 때 임의의 빈 슬롯을 탈의 동안만 사용하고, 퇴장 때 다시 임의의 빈 슬롯을 착의 동안만 사용한다. StateTree Editor 작업량: 낮음, 두 시설 선택 상태의 공용 슬롯 조회 바인딩 수정.
- B: 입장 때 고른 슬롯을 퇴장할 때까지 계속 예약하고 같은 곳에서 착의한다. StateTree Editor 작업량: 낮음, 장기 reservation 유지와 재조회 추가.
- C: 탈의·착의의 각 몽타주마다 새로운 슬롯을 선택한다. StateTree Editor 작업량: 중간, 행동별 선택·해제 상태 추가.
- 권장안: A — 락커를 임시 행동 지점으로 사용해 회수 제약을 줄이면서 한 번의 탈의 또는 착의 행동은 같은 자리에서 완료한다.
- 답변: A

- B: 탈의에 사용한 락커 슬롯이 의류 상태를 퇴장 때까지 소유한다.
- C: 전역 의류 저장소가 모든 손님의 의류 상태를 소유한다.
- 권장안: A — 입장과 퇴장에 서로 다른 락커를 사용해도 의류 상태가 손실되지 않고 손님 cleanup과 함께 정리된다.
- 답변: A

## Q85. 락커 회수 후 수용량이 현재 Lease 수보다 작아지면?
- A: 기존 손님은 유지하고 일시적 초과 수용 상태로 전환해 `ActiveLeaseCount < InstalledLockerCapacity`가 될 때까지 신규 체크인을 막는다.
- B: 현재 Lease 수 이하로는 락커를 회수하지 못하게 한다.
- C: 초과한 손님을 즉시 퇴장시킨다.
- 권장안: A — 플레이어의 설비 회수 자유를 보장하면서 이미 입장한 손님의 루틴과 물리 열쇠를 보존한다.
- 답변: B

## Q86. 회수 대상 묶음 락커에서 손님이 탈의·착의 중이면?
- A: 현재 몽타주를 중단하고 행동을 미완료로 유지한 채 다른 슬롯 대기열로 보내 같은 행동을 처음부터 재시작한다. StateTree Editor 작업량: 없음, 기존 native 몽타주 Task의 복귀 사유 확장.
- B: 해당 손님 행동이 끝날 때까지 묶음을 Draining 상태로 유지하고 완료 직후 자동 회수한다. StateTree Editor 작업량: 없음, native 회수 대기 transaction 필요.
- C: 해당 묶음의 모든 행동이 끝날 때까지 회수를 실패시킨다.
- 권장안: A — 대체 슬롯이 즉시 비어 있지 않아도 의류 상태를 보존한 채 회수를 완료할 수 있다.
- 답변: c

## Q87. 활성 손님에게 향후 착의가 필요한 동안 락커 슬롯을 0개까지 회수하면?
- A: 마지막 슬롯 회수를 실패시키고 최소 1개의 탈의·착의 지점을 유지한다.
- B: 0개 회수를 허용하고 락커가 다시 배치될 때까지 손님을 무기한 대기시킨다.
- C: 락커 없이 착의한 것으로 처리하고 루틴을 계속한다.
- 권장안: A — 플레이어가 모든 락커를 제거해 활성 손님 루틴을 영구 정지시키는 상태를 막는다.
- 답변: Q85 답변과 같이 락커 수용량은 현재 활성화된 손닙보다 낮게못함.

## Q88. 개별 락커 슬롯에 플레이어가 볼 수 있는 번호를 표시하는가?
- A: 표시하지 않고 내부의 안정적인 `LockerSlotId`만 사용한다.

- 권장안: A — 열쇠 번호와 락커 번호가 대응한다고 오해할 여지를 없애고 회수 후 번호 재할당도 제거한다.
