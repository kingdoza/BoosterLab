# QNA — 설비 배치 Authoring 단순화 기능 명세

각 질문의 `답변:` 뒤에 선택지를 하나 적어 주세요. 하나의 질문은 하나의 사용자 관찰 결과만 다룹니다.

## 확정 전제

- 설치 가능한 위치에서는 배치 설비와 같은 외형의 반투명 프리뷰를 표시합니다.
- 프리뷰는 충돌·Navigation·설비 등록과 게임플레이 상태를 만들지 않습니다.
- Zone Bounds 두께와 설비별 footprint 높이에 상관없이 모든 설비 바닥은 같은 Zone 바닥면에 놓입니다.
- 락커 Authority 미준비는 영구 오류로 보이지 않으며, 실제 확장 한도 초과만 설정 오류로 처리합니다.
- 기존 X/Y grid snap, 휠 회전, 충돌·구역·바닥 지지 검사, 회수와 Actor 변환 결과는 유지합니다.

## Q1. 설치할 수 없는 위치의 프리뷰 외관은 어떻게 표시할까요?

- A: 설치 가능은 초록 반투명, 설치 불가는 빨강 반투명으로 표시
- B: 가능 여부와 관계없이 항상 초록 반투명으로 표시하고 실패 이유만 prompt로 표시
- C: 설치 불가 시 프리뷰를 숨기고 실패 이유만 prompt로 표시
- 권장안: A — 현재 위치의 설치 가능 여부를 시선만으로 즉시 구분할 수 있습니다.
- 답변: A. 설치가능 프리뷰 머터리얼과 설치불가 프리뷰 머터리얼을 디벨로버 세팅에서 분리

## Q2. 시작 시 pre-placed 락커 총 칸 수가 확장 한도를 초과하면 어떤 락커를 활성화할까요?

- A: authored 상태에서 결정 가능한 고정 순서대로 한도까지 활성화하고 나머지만 비활성화
- B: 해당 월드의 pre-placed 락커를 모두 비활성화
- C: 락커마다 별도 우선순위를 authoring하고 높은 순서부터 한도까지 활성화
- 권장안: A — 별도 authoring을 늘리지 않으면서 시작 순서와 무관한 동일 결과를 만듭니다.
- 답변: A

## Q3. 범용 프리뷰는 설비의 어느 상태 외관을 보여줄까요?

- A: 설치 직후의 class-default 빈 상태·대기 상태 외관
- B: 회수 직전 설비의 물·내용물·가동 상태까지 그대로 복제한 외관
- C: 상태 표현을 제외하고 대표 몸체 메시 하나만 표시
- 권장안: A — 현재 회수 조건과 payload 계약을 유지하면서 새로 설치될 실제 설비 상태와 일치합니다.
- 답변: A
